# Specs (spec-driven development)

Antes de qualquer trabalho não-trivial neste repo, escreva um spec curto aqui em `specs/`
descrevendo: o problema, a proposta, e o que fica fora de escopo. Use `TEMPLATE.md` como base.

Fluxo:
1. Copie `TEMPLATE.md` para `specs/<nome-da-feature>.md`.
2. Preencha o spec antes de escrever código.
3. Implemente seguindo o spec; atualize o spec se a implementação divergir.
4. Specs ficam no repo como histórico de decisão — não apague specs antigos, mesmo depois de
   implementados.
